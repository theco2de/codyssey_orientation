### 수정 기록 1
- 발견한 문제: 폭 360px로 열어 달력을 보려고 했는데(테스트 내용) 달력과 ‘+ 평가 추가’ 버튼을 모두 보고 누를 수 있을 줄 알았다(예상 결과). 실제로는 화면에 떠 있는 둥근 ‘+ 평가 추가’ 버튼이 달력의 날짜 칸을 가렸다(실제 결과). 2-2의 테스트 3번에서 예상과 다르게 나온 결과이다. 평가 5건이 있는 화면에서 맨 위일 때 날짜 칸 6개와 겹쳤고, 스크롤을 많이 내리면 겹치지 않았다.
- AI에게 전달한 요청: “폭 360px에서 화면에 떠 있는 ‘+ 평가 추가’ 버튼이 달력 날짜 칸 일부를 가려. 기획서에는 폭 360px까지 달력과 버튼을 모두 보고 누를 수 있다고 적었어. 이 부분만 고치고, 다른 기능은 그대로 두고 고친 HTML 전체를 보여 줘.”
- 저장한 버전: `평가알리미_v1.html` → `평가알리미_v2.html`
- 수정 후 테스트 결과: 처음에는 떠 있는 버튼을 화면 아래 가로 바로 바꿨다. 같은 방법(Chrome에서 폭 360px, 맨 위일 때 버튼과 겹치는 날짜 칸 세기)으로 재 보니 겹치는 칸이 7개로 오히려 늘어서 이 방법은 버렸다. 이어서 좁은 화면에서는 떠 있는 버튼을 없애고 달력 바로 위 줄에 ‘+ 평가 추가’ 버튼을 두었다. 같은 방법으로 맨 위·중간·맨 아래에서 겹치는 날짜 칸이 모두 0개였고, 이 버튼을 누르면 입력 창이 열렸다. 폭 1000px에서는 이전처럼 떠 있는 버튼이 보이고 달력 위 줄의 버튼은 보이지 않았다. 기존 기능(안내 한 번만, 겹침 검사, 오늘의 평가, 안내 모두 지우기, 새로고침 유지, 달 이동)은 자동 점검에서 그대로 통과했고, 가로 스크롤도 없었다.
- 수정 이유: 떠 있는 버튼이 날짜 칸을 가리면 그 날짜를 눌러 일정을 보거나 추가하기 어렵고, 휴대폰으로 일정을 확인하는 사용자가 원하는 날짜를 놓칠 수 있다.

- 저장한 버전: `평가알리미_v3.html` → `평가알리미_v4.html`
- 수정 후 테스트 결과: 같은 방법(자동 점검 도구에서 입력 창 열기)으로 16:13에 열어 보니 예정 시각이 17:00으로 채워졌다. 구분을 ‘참여’로 저장하고 다시 열자 ‘참여’가 선택되어 있었고, 저장한 평가가 없을 때는 ‘요청’이었다. 날짜 모달에서 추가할 때는 이전처럼 그 날짜의 09:00으로 채워졌다. 기존 기능(달 이동, 안내 한 번만, 겹침 검사, 오늘의 평가, 안내 모두 지우기, 새로고침 유지)은 자동 점검에서 그대로 통과했다. 아직 확인하지 못한 것: 실제 Chrome에서 입력 창의 시각 칸 모양, 사용자가 다시 써 보고 불편이 줄었는지.
- 수정 이유: 평가를 하나 등록할 때마다 어중간한 시각을 지우고 구분을 다시 고르는 일이 반복되면 입력이 번거로워 일정을 놓치거나 입력을 미루게 된다. 이 수정으로 입력할 값이 줄어든다. 다만 자동으로 가져오는 것은 아니며, 날짜가 오늘이 아닌 평가는 여전히 날짜와 시각을 직접 고쳐야 한다.

### 추가 반영: 텔레그램 알림 (수정 기록 3건과 별개)

이 반영은 테스트에서 찾은 문제를 고친 것이 아니라, 사용자가 요청해서 넣은 기능이다. 그래서 수정 기록 3건에는 세지 않았다.

- 요청한 이유: 이 탭을 다른 탭이나 다른 앱 뒤에 두면 화면 안의 안내가 보이지 않아, 휴대폰으로도 알림을 받고 싶었다. 사용자가 보낸 요청은 “현재 버전에서 telegram으로 알림이 오도록 할 수 있을까?”였고, 이어서 “chat_id를 입력하도록 하고 기본 기능으로 넣는 정도만 가능하면 하고 싶어. 우선 적용되는지 확인하고 문서에 넣자”라고 했다.
- 먼저 확인한 것: Chrome에서 로컬 파일과 같은 출처(`null`)로 가짜 토큰을 써서 텔레그램 서버에 요청했다. GET과 폼 형식(`x-www-form-urlencoded`) POST는 서버 응답을 읽을 수 있었고, JSON 형식 POST는 브라우저가 막았다. 그래서 폼 형식으로 보내기로 했다. 사용자가 만든 봇으로 서버 없이 보낸 테스트 요청은 텔레그램 서버가 성공(메시지 번호가 있는 응답)으로 받았다.
- 저장한 버전: `평가알리미_v4.html` → `평가알리미_v5.html`
- 테스트 결과: 가짜 응답으로 점검했다. 설정 창, 잘못된 값 거부, 테스트 메시지 전송(폼 형식 POST), 2분 전에 한 번만 전송, 새로고침 뒤 설정 유지와 재전송 없음, 꺼져 있거나 2분보다 먼 평가는 전송 안 함, 전송 실패 안내, chat_id 찾기(없음·1개·여러 개), 설정 지우기가 모두 기대대로였다. 토큰은 HTML 파일, 평가 목록 저장값, 알림 기록에 들어가지 않았다. Chrome에서 폭 360px와 900px로 열었을 때 설정 창이 화면에 들어갔고, 처음에는 토큰 입력칸이 다른 칸보다 좁아서 고쳤다. 기존 기능은 자동 점검에서 그대로 통과했다. 사용자가 직접 텔레그램 알림이 오는 것을 확인했다.
- 지키려고 한 것: 토큰은 코드에 적지 않고 설정 창에서 입력받아 이 탭에만 저장한다. 설정하지 않아도 모든 기능이 동작한다(선택 설정). 테스트 중 토큰을 대화에 붙여 넣은 일이 있어, 확인이 끝난 토큰은 폐기하도록 안내했다. 이 기록에는 토큰과 chat_id 값을 적지 않았다.
- 확인하지 못한 것: 실제 휴대폰에서 이 페이지를 연 화면, 로컬 파일(`file://`)로 연 화면에서의 설정 창 모양.

## 사용자 테스트

- 테스트 참여자와 요청한 작업: 가족 1명에게 사용법을 설명하지 않고 “내일 오후 3시 평가를 등록해 봐”라고 부탁했습니다. 사용한 파일은 `평가알리미_v3.html`입니다.
- 사용자의 행동과 질문: 특별한 행동이나 질문은 없었습니다. 오작동도 없었습니다.
- 받은 피드백: “자동으로 평가가 들어오면 좋겠어. 수동으로 넣으니까 불편해.”
- 반영 내용과 결과: 이 피드백(평가가 자동으로 들어오기)의 ‘자동’은 이번에는 구현하지 않았다. 코디세이(usr.codyssey.kr)의 평가 정보는 로그인한 상태에서만 받을 수 있고 공개된 API를 확인하지 못했으며, 이 페이지는 로그인·API 키·서버 없이 HTML 파일 하나로 열려야 하는 제약이 있어 현재는 구현하기 어렵다고 판단했다. 코디세이의 ‘월간 일정 목록’을 복사해 붙여 넣는 방법도 살펴봤지만, 그 목록에는 과제 이름과 상대방, 요청·참여 구분이 없어 자동으로 정확히 채울 수 없어서 만들지 않았다. 기획서의 ‘추가 기능’에 이 항목과 이유를 적어 두었다. 대신 사용자가 말한 불편(수동 입력)을 줄이기 위해 입력 창의 기본값을 바꾸는 수정 3(`평가알리미_v4.html`)으로 일부 반영했다. 사용자에게 다시 써 보게 하는 재테스트는 아직 하지 않았다.
